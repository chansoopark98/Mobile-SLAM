## 정확히 제한된 보충 semantic 판정

- 원래 strict result는 항상 원본 상태로 보존. 보충 파일은 별도 `supplemental-assessment.json` 등으로 작성; `strictStatus`, 원본 mismatch frame/field/count/termination, concrete proof 경로를 필수 포함
- 기존 old `fce250…` room4 frame1973 proof/peer 승인은 **old artifact에만 적용**. New source/candidate에서는 원인을 재측정하기 전 재사용/추정 승인 금지
- 보충 허용 대상: pinned Ceres의 실제 **finite exact-zero FUNCTION-tolerance stop, effective function tolerance0**와 다른 플랫폼의 actual max10 종료 조합만
- 각 mismatch마다 같은 새 artifact/source/options/input을 재현한 bounded capture의 실제 message·finite initial/final cost·current usable/fresh/finite update·timestamp/상태/epoch를 확인. Native/WASM pose cap·coverage/init·일반 상태 차이는 기존 기준 그대로 만족 필요
- Ceres source의 function check/summary append 순서와 captured rows로 count 차이 설명. Append 이전 반환의 미저장 trial은 source-derived attempted work로 명시; 그 trial의 step/gradient를 직접 측정값으로 생성 금지
- 금지된 확대: 모든 `CONVERGENCE↔NO_CONVERGENCE`, gradient/parameter0·stationary optimum, time/min-radius, invalid step, NaN/evaluation failure, unusable solve를 같은 예외로 묶기
- 원인·입력/profile/source 불일치 또는 cap/current validity 실패는 보충 PASS 불가. 각 새 mismatch의 concrete proof 없으면 `unproven` 유지
- 허용 표기: **numeric/current-usable/method parity PASS WITH PROVEN FUNCTION-STOP EXCEPTION; strict solver summary equality FAIL**. Counter/termination normalization·cap widening·원래 contract/report의 PASS 재작성 없음
- 이 보충은 field/production accuracy 또는 전체 strict gate 통과 판정 제외. Strict pilot freeze 실패 뒤 별도 numeric/method freeze가 필요하면 parent가 새 분리 정책을 먼저 명시; 기존 runner/comparer assert 우회 없음
